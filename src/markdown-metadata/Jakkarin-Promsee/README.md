I have to *see* a thing work before I trust it. I proved linear regression without
matrices and worked out double descent on my own — because I wanted to watch how
intelligence actually lives inside a single weight. When I couldn't get access to a
real neuron, I started building one out of capacitors.

One rule sits under all of it: **the fast answer destroys creativity.** So I build
from intuition first and read the literature afterward — not to be taught, but to
find out what the thing I built is already called. My range runs the whole stack,
because I don't believe a layer until I've built it myself: analog circuits, FPGA
hardware, systems programming, machine learning from scratch, and full-stack
products.

## Selected work

**[bio-analog-cpu](https://github.com/Jakkarin-Promsee/bio-analog-cpu)** — my main
research. A bio-inspired analog compute substrate that learns *on the chip, while it
runs*: weights live as charge on capacitors, the multiply-accumulate happens as
physical current in the wires, and no backward pass ever leaves the chip. An
independent, ~8-month solo project — survived one full collapse and rebuild.
*Python simulation · analog circuit design · compute-in-memory · on-chip learning.*

**[ChronoForge](https://github.com/Jakkarin-Promsee/chronoforge-fpga-engine)** — a 2D
game engine that runs as *pure hardware*: no CPU, no OS, no instruction set. You
author games in Python; they execute directly as event-driven Verilog at 640×480 @
60 Hz on a Basys3 FPGA, inside ~18k LUTs. *Verilog · Python · FPGA · digital design.*

**[discretization-of-gradient-flow](https://github.com/Jakkarin-Promsee/discretization-of-gradient-flow)**
— Explicit, Implicit, and Newton gradient descent, built from scratch in NumPy with
the full mathematics written out: Taylor expansions, the Hessian, eigen-decomposition,
and convergence behavior. *NumPy · optimization theory · machine learning from scratch.*

**[ctplot](https://github.com/Jakkarin-Promsee/ctplot)** — a terminal plotting library
in pure, dependency-free C, with hand-rolled "OOP in C" underneath it. The question
that started it: could I build object-orientation in a language that doesn't have it?
*C11 · systems programming · zero dependencies.*

**[Hot Potato](https://github.com/Jakkarin-Promsee/hot-potato-client)** — an
AI-powered learning platform where teachers author critical-thinking lessons and
students learn with an AI tutor. *React 19 · TypeScript · Node.js · MongoDB · Gemini.*

## Where I'm headed

Research — specifically the seam between **machine-learning theory, neuromorphic
computing, and computer architecture**: non-von-Neumann substrates, analog and
compute-in-memory hardware, and learning rules that keep running for a lifetime
instead of freezing the moment training stops. I'm drawn to open problems far more
than to routine engineering, and this is the direction I want to spend the next years
going deep on.

## How I work

Intuition first, literature second. I build a mechanism until it stands on its own,
then read the field to see what it's called — and I've been right often enough to
trust it. Most of what I know, I learned by building it wrong first; the analog
processor above collapsed once at its root and came back stronger for it. I work in
the open and write up the failures next to the wins, because being corrected by
reality is the whole point.
